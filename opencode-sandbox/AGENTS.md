# AGENTS.md — opencode-sandbox

**Precedence:** the closest `AGENTS.md` to the files you're changing wins. This file governs `opencode-sandbox/`; the sibling `../local-models/AGENTS.md` governs host model serving.

Runs OpenCode 2 inside Docker Sandboxes (`sbx`, schema v3 workload kit) with the agentmemory MCP. Read [README.md](README.md) before changing the flow; [opencode-sandbox.yaml](opencode-sandbox.yaml) is the kit contract and [opencode-sandbox.dockerfile](opencode-sandbox.dockerfile) builds the image.

## Commands (host, Debian; installs take minutes)
| Task | Command | Notes |
|------|---------|-------|
| Install host deps | `./scripts/install-dependencies.sh` | sbx 0.51.0 (amd64/arm64 deb, pinned SHA-256) + agentmemory 0.9.32 (needs Node >= 20 and a writable npm prefix); flags `--skip-docker-sandbox`, `--skip-agentmemory`; needs KVM + `sbx login`; the kit image bakes OpenCode 2.2.6 (`@opencode/cli`) and agentmemory 0.9.32 at build time |
| Sync repo config to host | `./scripts/sync-config.sh` | host only, never inside the sandbox; copies opencode.json, global-AGENTS.md (as AGENTS.md), plugins/, commands/ into ~/.config/opencode; validates JSON, keeps a single `*.bak` per file, overwritten every run; also renders/enables the `agentmemory-ollama-proxy` systemd user unit, replaces `~/.agentmemory/.env` from the repo after backing it up, and pulls/validates the embedding model when the repo env selects one; `--skip-agentmemory-env` opts out of the env replacement |
| Install/update skills | `sbx skills add mattpocock/skills` (first time) / `sbx skills update` | host only; the runtime mounts the sbx shared store via the kit's `agent-skills@1` capability; host custom skills load from the read-only host mount through the `skills` config field; new store entries need a sandbox restart |
| Approve GitHub credential | `./scripts/setup-github-credential.sh` | host only; idempotently merges the `github` apiKey binding into ~/.config/sbx/credentials.yaml (required: the kit is third-party), reports whether a github service secret is stored |
| Enter sandbox | `./scripts/run-opencode-in-docker-sandbox.sh` | run from any project dir; requires sbx and ~/.config/opencode; sandbox name = sanitized basename of $PWD (lowercase, hyphens, 63 chars), reused if it exists; starts OpenCode with `--auto` |
| Reset sandbox | `sbx rm <name>` then relaunch | required after `opencode-sandbox.yaml` or `opencode-sandbox.dockerfile` changes; also required once for existing v2 sandboxes, which cannot be updated in place; `agentmemory.env` only needs a wrapper stop/start |
| Run LLM repair proxy | `systemctl --user status agentmemory-ollama-proxy` | installed, enabled and restarted by `./scripts/sync-config.sh`; listens on `127.0.0.1:11435`; verify with `curl -s http://127.0.0.1:11435/api/version` |
| Start/stop host agentmemory | `./scripts/agentmemory-host.sh --background` / `./scripts/agentmemory-host.sh stop` | host only, never inside the sandbox; the wrapper is also the supervisor: it health-checks `/agentmemory/livez`, restarts the server with capped backoff and restarts the worker if it dies; `--background` detaches the supervisor, foreground keeps it in the terminal; runs the project-scope migration after each start/recovery; `status` shows supervisor, server and worker; pidfiles, logs and retry state live under `~/.local/state/agentmemory-host/` |
| Snapshot / list / prune | `./scripts/agentmemory-snapshot.sh [--list] [--keep N] [--no-prune] [--rebuild]` | host only; `sync-config.sh` installs the weekly `agentmemory-snapshot.timer` (keep 3, override with `AGENTMEMORY_SNAPSHOT_KEEP`); keeps the newest restore points by re-rooting the snapshot repo, not by resetting backwards; every git call runs in a 2 GiB `systemd-run` scope and the job is capped at 3 GiB, and history/size beyond `keep + 2`/2 GiB rebuilds from the newest `state.json` instead of replaying it; restore through `POST /agentmemory/snapshot/restore` with a hash from `--list` |

## File Map
| Path | Purpose |
|------|---------|
| opencode-sandbox.yaml | v3 workload kit descriptor: required `home` arg, version args, network allowlist, GitHub `credential@1`, lifecycle install, `agent-skills@1`, `agent-context@2` |
| opencode-sandbox.dockerfile | image build: `docker/sbx-kit-shell:1.0.0`, bakes OpenCode 2.2.6 + agentmemory 0.9.32, persistent shell exports host config path, agentmemory secret and websearch keys from the read-only mount |
| opencode.json | native OpenCode 2 config: providers (ollama/llama-server on 172.17.0.1), mcp.servers, permissions, a pinned `websearch.provider` (`"random"`), provider policies, update disable; `instructions`/`skills` point at the host config mount |
| global-AGENTS.md | global instructions; synced to ~/.config/opencode/AGENTS.md and loaded through the `instructions` field in opencode.json |
| agentmemory.env | source of truth for `~/.agentmemory/.env` (LLM, proxy, embeddings/backfill); `sync-config.sh` replaces the host file with it (backup first) unless `--skip-agentmemory-env` is passed |
| scripts/agentmemory-ollama-proxy.mjs | host-only OpenAI-compatible proxy in front of Ollama for agentmemory: forces greedy sampling, caps compression `max_tokens` (default 800, `COMPRESSION_MAX_TOKENS`) to fit agentmemory's hardcoded 60s compression deadline, escapes bare `&` in responses so the strict XML compression parser accepts shell observations, and gates chat completions (`MAX_INFLIGHT` default 2, `MAX_QUEUE` default 8) with a fast 503 + `Retry-After` so parallel sessions cannot pile up generation work; `GET /proxy/metrics` exposes the counters; listens on 127.0.0.1:11435 |
| scripts/agentmemory-ollama-proxy.service | systemd user unit template for the proxy; `sync-config.sh` substitutes the absolute node and repo paths and installs it to ~/.config/systemd/user/ |
| scripts/agentmemory-host.sh | host-only lifecycle wrapper and supervisor: runs agentmemory from `$HOME/.local/share/agentmemory` with `NODE_OPTIONS=--max-old-space-size=4096`, restarts it after consecutive health failures, runs the idempotent project-scope migration, starts/stops `scripts/agentmemory-compression-retry.mjs` and restarts it if it dies, rotates `server.log`/`retry.log`/`supervisor.log` at 10 MB while running (copy-and-truncate, so live append writers keep their descriptor), and keeps pidfiles/logs/retry state under `~/.local/state/agentmemory-host/` |
| scripts/agentmemory-compression-retry.mjs | host-only retry worker for observations marked compression failed; retries only completed (non-active) sessions, skips a pass entirely while any session is active (`AGENTMEMORY_RETRY_IDLE_ONLY`, default on, recheck `AGENTMEMORY_RETRY_ACTIVE_INTERVAL_MS` default 2m), follows the per-session server cursor, caps attempts at 6 but rechecks capped items after `AGENTMEMORY_RETRY_CAPPED_AFTER_MS` (default 24h) so proxy-503 rejections drain the same day, no-ops until the server, proxy, LLM provider and vector backfill are ready; `--watch` under the wrapper, `--once` for a manual pass |
| scripts/agentmemory-snapshot.sh | host-only create/list/prune wrapper over the snapshot API; keeps the newest N commits by re-rooting the snapshot repo (a backward reset would keep the oldest), refuses to prune a repo without `state.json`, locks against overlapping timer/manual runs, disables git auto-gc (the server's own commit would otherwise run `gc --auto`), runs every git call in a 2 GiB `systemd-run` scope with an uncapped retry only for scope/signal failures (never OOM), and rebuilds from the newest committed `state.json` into a staging repo that is swapped in atomically — a failed rebuild leaves the previous repo intact; `--rebuild` does that on demand |
| scripts/agentmemory-snapshot.service, .timer | systemd user units installed by `sync-config.sh`; weekly snapshot (`OnCalendar=weekly`, `Persistent=true`), keep 3 by default; the service runs `Nice=19`/idle I/O with `MemoryMax=3G` and `MemorySwapMax=0` so a pathological git dies instead of thrashing the host |
| scripts/install-dependencies.sh | host setup: sha256-verified sbx deb, KVM checks, Node/npm guards, agentmemory install |
| scripts/run-opencode-in-docker-sandbox.sh | launcher: preflight checks (sbx, config dir), sanitizes sandbox name, resolves AGENTMEMORY_SECRET, writes ~/.config/opencode/agentmemory-secret (0600), health-checks :3111, mounts `~/.config/opencode` read-only as an extra workspace, starts OpenCode with `--auto` (no approval prompts) |
| scripts/sync-config.sh | repo to ~/.config/opencode; aborts when plugins/ or commands/ are symlinks (that is the sandbox view) |
| scripts/setup-github-credential.sh | host-only: ensures the `github` apiKey binding (api.github.com, github.com) in ~/.config/sbx/credentials.yaml without clobbering other bindings, reports whether a github service secret is stored |
| commands/recall.md, commands/remember.md | /recall and /remember slash commands over agentmemory tools |
| plugins/agentmemory-capture.ts | OpenCode 2 plugin (`@opencode/plugin`): subscribes to events and registers prompt/context/compaction/tool hooks; injects a title-only pointer to recent project sessions while the conversation has no assistant turn (new session or after `/clear`), compaction injects the full `/context` budget; failed capture writes (`/observe`, session lifecycle) are spooled to a bounded JSONL queue in the sandbox and replayed every 30s (summaries/consolidation stay best-effort so replays do not duplicate model calls); cleanup posts synchronously via curl and spools on failure |
| examples/opencode_project_skills_path_example.json | example `skills` config field for project-local skills |

## Heuristics
| When | Do |
|------|-----|
| Changing opencode.json, global-AGENTS.md, plugins/, commands/ | run `./scripts/sync-config.sh`, restart OpenCode; no sandbox rebuild needed |
| Changing your own skills under `~/.config/opencode/skills` | edit them on the host; they are read live from the read-only host mount through the `skills` config field; start a new session to pick up additions |
| Wanting zero approval prompts | use the launcher: it passes `--auto` and opencode.json allows every action except the explicit denies (agentmemory tools, git push); `sbx run`/dashboard attaches skip the flag |
| Changing `opencode-sandbox.yaml` or `opencode-sandbox.dockerfile` | recreate the sandbox (`sbx rm <name>`), then relaunch; after kit edits run `sbx kit validate --kit-arg "home=$HOME" .` (v3 source validation may require the build); allow entries are additive to the user's preset and pinned versions must match the install script. `agentmemory.env` only needs a wrapper stop/start |
| Sandbox cannot reach host model servers at 172.17.0.1 | sbx proxies all TCP; non-Open network presets may deny the bridge gateway (allow it scoped, or use host.docker.internal baseURLs; see README troubleshooting) |
| Porting or editing the capture plugin | OpenCode 1 plugins do not run in OpenCode 2; use the `@opencode/plugin` 2.2.6 API. Local plugin files resolve the package from the loader, no node_modules needed |
| Needing global instructions | edit global-AGENTS.md; it syncs to ~/.config/opencode/AGENTS.md and opencode.json loads it through the `instructions` field |
| Adding an agentmemory tool deny | put it after the allow rule in `permissions`; last matching permission rule wins |
| Adding or updating the mattpocock skills | run `sbx skills add mattpocock/skills` on the host the first time, then `sbx skills update`; the runtime mounts the shared store via `agent-skills@1`, and new store entries appear after `sbx stop <name>` and relaunch |
| Making host skills available in sandboxes | put them under `~/.config/opencode/skills`; the host config mount is read-only and opencode.json loads them through the `skills` field. Do not use `sbx skills import` for them unless you intentionally want copies in the shared store |
| Shared skills missing inside the sandbox | check `sbx skills ls` on the host; verify the kit's `agent-skills@1` capability and that the sandbox was created with the v3 kit, then `sbx stop <name>` and relaunch |
| Skill not offered by the model, or manual invocation | user-invoked skills (`disable-model-invocation: true`, e.g. `grill-me`) are absent from the model's list by design; open the `/skills` picker and select one (it inserts `@<skill>`), or mention `@<skill>` in the prompt |
| Giving OpenCode Console/Go its API key | store it before sandbox creation with `sbx secret set-custom --host opencode.ai --env OPENCODE_API_KEY`; sbx injects the placeholder and OpenCode 2 reads it as the `opencode` integration environment connection used by the `opencode-go` provider. Do not declare `OPENCODE_API_KEY` in `opencode-sandbox.yaml`, write `auth.json`, or use `/connect`: V2 keeps credentials in SQLite and `/connect` puts the real key inside the sandbox |
| Giving sandboxed `gh` GitHub access | run `./scripts/setup-github-credential.sh` (approves the `github` binding; required because the kit is third-party) and store a fine-grained PAT (Contents: Read-only; Issues and Pull requests: write) with `sbx secret set github`; sandboxes started before the binding need `sbx stop <name>`; the proxy injects the token, the sandbox only ever sees a sentinel |
| Keeping pushes on the host | `git push` is denied by the shell rules in opencode.json (after the allow catch-all); the stored PAT has no Contents:write and no GitHub SSH key is loaded; the user pushes manually |
| Host agentmemory health check fails | expected path; the sandbox runs a reduced local toolset until host :3111 is back. Capture writes are spooled to `~/.local/share/opencode-agentmemory-spool/pending.jsonl` in the sandbox (5 MB / 7 days) and replay every 30 s; the spool dies with `sbx rm` |
| Snapshots or restore points | the weekly `agentmemory-snapshot.timer` runs `scripts/agentmemory-snapshot.sh --keep 3`; list with `--list` and restore through `POST /agentmemory/snapshot/restore` with the commit hash. `SNAPSHOT_ENABLED=true` must be in the host env (it is in the repo `agentmemory.env`) and takes effect after a server restart. If the repo grew huge or pruning OOMs, run `--rebuild` (drops history, keeps the newest `state.json`). Never raise `SNAPSHOT_INTERVAL` above 2147483: Node clamps larger `setInterval` delays to 1 ms and the server then snapshots every few seconds |
| Rolling back a supervisor/worker/plugin change | the repo is a local git repository (branch `main`, initial commit included); edit, commit, and restart the affected process. Never push |
| Starting or stopping host agentmemory | use `./scripts/agentmemory-host.sh --background` (or foreground) and `./scripts/agentmemory-host.sh stop`; the wrapper supervises the server and restarts the retry worker if it dies. Never run `agentmemory` directly or start a second instance; `status` shows supervisor, server and worker |
| Parallel sessions/subagents make compression time out | the repair proxy gates chat completions: `MAX_INFLIGHT` (default 2) run at once, `MAX_QUEUE` (default 8) compression requests wait, and beyond that it answers `503` + `Retry-After` so observations stay raw instead of queueing past the 60s deadline. Summaries and consolidation jump ahead of queued compression. Check `curl -s http://127.0.0.1:11435/proxy/metrics` for `inflight`/`queued`/`rejected`; a rising `rejected` means the local model is too slow for the session count |
| Failed compression items accumulate | the supervisor keeps the retry worker alive; with the model warm, retries recover in 10-35s. The worker skips any pass while a session is active (`AGENTMEMORY_RETRY_IDLE_ONLY`, rechecks every 2m) so it never competes with live compression, and revisits attempt-capped observations after 24h. Check `~/.local/state/agentmemory-host/retry.log` and `supervisor.log`, or run `node scripts/agentmemory-compression-retry.mjs --once` on the host. Failed observations are still stored, indexed and embedded |
| Observations keep failing with `compression_failed` on a local model | agentmemory hardcodes a 60s compression deadline (including its stricter retry); the proxy caps compression `max_tokens` at `COMPRESSION_MAX_TOKENS` (default 800). Lower it or keep the model warm (`OLLAMA_KEEP_ALIVE=-1`) if timeouts persist; cold loads cost ~37s and eat the budget |
| Where `AGENTMEMORY_SECRET` lives | `~/.agentmemory/secret` (0600), generated on first start; normally not in `~/.agentmemory/.env`. `sync-config.sh` replacing the env does not rotate it. Deleting it rotates; re-run the launcher and restart the sandbox |
| agentmemory status says `Provider: noop`, or compression stays `raw` | v0.9.x needs `AGENTMEMORY_LLM_PROVIDER=openai`; a provider key alone is noop. Run `./scripts/sync-config.sh` (it replaces `~/.agentmemory/.env` from the repo), then restart through `./scripts/agentmemory-host.sh stop` and `./scripts/agentmemory-host.sh` |
| Compression logs `parse_failed` or observations stay `raw` | the host repair proxy is not running, or `OPENAI_BASE_URL` is not `http://127.0.0.1:11435/v1`. Local models emit raw `&&` in shell facts, which agentmemory's XML parser rejects; the proxy forces greedy sampling and escapes bare `&`. Check `curl -s http://127.0.0.1:11435/api/version`, then restart through the wrapper |
| Changing the embedding model or `OPENAI_EMBEDDING_DIMENSIONS` | agentmemory refuses to start on stale vectors (or discards them if `AGENTMEMORY_DROP_STALE_INDEX=true`). Set that flag, restart once to re-embed the whole store, then remove it. `sync-config.sh` verifies the model's real width against the env before you restart |
| Moving the repo checkout or changing the `node` binary | re-run `./scripts/sync-config.sh`; it re-renders the proxy unit with the new absolute paths and restarts it |
| Customizing the host agentmemory env | edit repo `agentmemory.env`; `sync-config.sh` replaces `~/.agentmemory/.env` with it and keeps the old file at `.env.bak`. Pass `--skip-agentmemory-env` to preserve host-only edits. The secret lives in `~/.agentmemory/secret`, not the env file, so the backup does not contain it |
| Calling agentmemory MCP tools | pass `concepts` and `files` as comma-separated strings; the MCP schema rejects arrays |
| Editing ~/.config/opencode directly | don't; it is a read-only mount in the sandbox, the repo is the source of truth |

## Boundaries
- Never commit secrets, the agentmemory-secret file, or `~/.agentmemory/.env`. The GitHub token lives only in the host sbx secret store (`sbx secret set github`), never in the repo or ~/.config/opencode.
- Start and stop the host agentmemory server only through `scripts/agentmemory-host.sh`; it owns the bounded compression-retry worker.
- Never call `sbx run` on the kit directly; the launcher supplies the required `home` kit arg.
- Ask first: changing the `opencode-sandbox.yaml` schema or args, `opencode-sandbox.dockerfile`, MCP deny rules, or pinned dependency versions.
